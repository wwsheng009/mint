# TUI Line Padding 问题：应该在哪个层面解决？

## 一、问题的本质

```
场景：重绘一行内容
┌─────────────────────────────────┐
│ 旧行: 🎨 component (20 cells)    │  ← 🎨是宽字符(2 cells)
│ 新行: Label (18 cells)            │  ← 普通文本
└─────────────────────────────────┘

重绘后:
┌─────────────────────────────────┐
│ Label │                        │  ← 新内容18 cells
│      ↑ 第19 cell 还是 🎨 的continuation
└─────────────────────────────────┘

结果：边框看起来塌陷了2个字符
```

## 二、应该在哪里解决？

### 方案对比

| 层面 | 方案 | 优点 | 缺点 |
|------|------|------|------|
| **Buffer层** | `SetLine(x,y,text)` 自动填充 | 所有写入统一 | 需要新API，破坏现有接口 |
| **Paint层** | 渲染器级行填充 | 不侵入Buffer | 需要知道组件边界 |
| **组件层** | 各组件自己填充 | 简单直接 | ❌ 重复代码，容易遗漏 |
| **布局层** | Flex容器自动填充 | 最优雅 | 需要修改Layout引擎 |

## 三、理想方案：布局层自动填充

```go
// runtime/ui/layout.go
func (v VStackBuilder) Build() ui.VNode {
    vstack := &VStack{...}
    
    // 渲染时自动填充每一行到容器宽度
    vstack.SetFillToEnd(true)
    
    return vstack
}
```

这样任何内容在VStack中都会自动填充到容器边界。

## 四、当前状态：为什么只有TreeView有这个问题？

因为其他的UI组件都是固定宽度的：
- Button: 固定宽度
- Input: 固定宽度
- Text: 任意长度，但通常不聚焦切换

只有TreeView：
1. 混合使用窄字符和宽emoji（📦 🎨 📝）
2. 通过方向键切换焦点
3. 不同行的宽度差异很大

## 五、推荐解决方案

### 短期：保持TreeView内部填充
- ✅ 立即生效
- ✅ 不破坏现有API
- ❌ 局部修复，其他组件仍有同样风险

### 长期：布局层自动填充
- 修改 `VStack`、`HStack` 的渲染逻辑
- 添加 `SetFillToEnd()` 选项
- 所有子元素自动填充到容器边界

## 六、关键代码位置

```

  - 第854行: 填充逻辑
```

## 七、其他可能受影响的地方

需要检查是否还有类似问题的地方：
1. Input组件 - 用户输入时长度变化
2. 文本编辑组件 - 光标移动和内容变化
3. 任何动态更新内容的组件
