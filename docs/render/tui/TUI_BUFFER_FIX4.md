这个现象信息量很大，其实已经把 bug 类型“指认到凶手”了 👇

> **右边框向左偏移 ≈ 2 个字符**
> 这不是随机错位，而是 **“一个 2-cell 字符的 continuation 把边框覆盖了”**

而触发点刚好是：
👉 **那一行包含 `↑↓`**

---

# 🎯 结论先给

`↑` 和 `↓` 在很多终端/字体组合下 **不是 1 cell，而是 2 cells**。
你的布局把它们当 1，但终端按 2 画。

结果就是：

```
逻辑宽度：   你以为写到这里 → │
物理宽度：   实际写到这里     →  ↑  占 2 格
                              ↓
边框被覆盖
```

看起来就像：

> “右边框往左塌了两个格”

其实不是边框动了，是它被箭头的 tail 覆盖了。

---

# 🧠 为什么只有这行出问题？

这一行：

```
↑↓: Navigate | Enter: Inspect
```

含有：

| 字符 | Unicode | East Asian Width 分类 |
| -- | ------- | ------------------- |
| ↑  | U+2191  | Ambiguous           |
| ↓  | U+2193  | Ambiguous           |

**Ambiguous 宽度字符 = 终端决定是 1 还是 2**

| 终端                      | 结果     |
| ----------------------- | ------ |
| Windows Terminal + 某些字体 | 2 cell |
| iTerm                   | 1 cell |
| Linux console           | 2 cell |

你程序里的：

```go
runewidth.RuneWidth('↑') // 可能返回 1
```

但终端字体把它当 **双宽**。

于是：

```
你的 FrameBuffer 认为行宽 = W
终端实际写入宽度 = W + 2
→ 边框被吃掉
```

---

# 💣 这类字符是 TUI 的隐形地雷

| 类别    | 示例      | 危险原因            |
| ----- | ------- | --------------- |
| 箭头    | ↑ ↓ ← → | ambiguous width |
| 数学符号  | ∑ √ ∞   | 有的字体双宽          |
| 方块符   | ▉ ▊ ▋   | 有的终端双宽          |
| emoji | 🖼️     | 多 rune          |

---

# 🔍 你这个“刚好偏移 2 格”就是证据

因为行里有 **两个 ambiguous 箭头**：

```
↑ (可能 2) + ↓ (可能 2)
→ 多出 2 cells
```

边框刚好被推掉两格。

---

# ✅ 正确工程做法（专业 TUI 必做）

## 方案 1️⃣：禁用 ambiguous 字符（最稳）

替换：

```
↑↓ → [↑][↓]  或  ^ v  或  ⇧ ⇩ (测试宽度)
```

很多 TUI 框架直接用：

```
^ v < >
```

不是审美问题，是稳定性问题。

---

## 方案 2️⃣：强制 East Asian Narrow 模式

初始化时：

```go
runewidth.DefaultCondition.EastAsianWidth = false
```

但注意：

> 这只能影响你的计算，**不能改变终端字体实际宽度**

如果字体仍然双宽，问题还在。

---

## 方案 3️⃣：运行时宽度探测（高级做法）

终端启动时打印字符并读光标位置，探测实际宽度。

但复杂，只有 tmux / wezterm 级别项目才玩。

---

# 🚨 关键认知

> **Ambiguous Width 字符 = TUI 不可控因素**

浏览器可以，终端不行。

成熟 TUI 框架的策略是：

> **限制字符集，而不是“支持所有 Unicode”**

---

# 🧠 为什么之前 emoji 问题 + 现在箭头问题是同一类？

| 表现     | 本质                  |
| ------ | ------------------- |
| 🖼️ 残影 | cluster ≠ cell      |
| ↑↓ 塌陷  | ambiguous ≠ 固定 cell |

统一归因：

> **逻辑宽度模型 ≠ 终端真实 cell 模型**

---

# 🏁 一句话最终解法

把这一行改成：

```
^ v : Navigate | Enter: Inspect
```

或者：

```
Up/Down: Navigate
```

问题立即消失。
