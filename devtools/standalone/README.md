# Standalone DevTools - 独立调试器

独立调试器是一个与被调试程序**完全分离**的调试工具。即使被调试程序崩溃或无法正常运行，独立调试器仍然可以分析已记录的日志。

## 核心优势

```
┌─────────────────────────────────────────────────────────────────┐
│                      传统嵌入式 DevTools                         │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────┐                                                │
│  │  被调试程序  │                                                │
│  │  ┌────────┐ │  ❌ 程序崩溃时 DevTools 也无法工作              │
│  │  │DevTools│ │  ❌ 无法观察程序启动阶段                        │
│  │  └────────┘ │  ❌ 调试工具本身可能影响程序行为                │
│  └─────────────┘                                                │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                      Standalone DevTools                        │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────┐           ┌─────────────┐                      │
│  │  被调试程序  │  日志文件  │  独立调试器  │                      │
│  │    Logger   │──────────▶│   Debugger  │                      │
│  │             │           │             │                      │
│  └─────────────┘           └─────────────┘                      │
│       ✅ 程序崩溃后仍可分析日志                                  │
│       ✅ 调试器不干扰被调试程序                                  │
│       ✅ 可以事后分析                                           │
└─────────────────────────────────────────────────────────────────┘
```

## 快速开始

### 1. 在被调试程序中使用 Logger

```go
import "github.com/wwsheng009/mint/devtools/standalone"

func main() {
    // 创建 Logger
    logger, err := standalone.NewLogger(nil)
    if err != nil {
        panic(err)
    }
    defer logger.Close()

    // 记录事件
    logger.LogComponentAdd("btn1", "Button", map[string]interface{}{
        "text": "Click Me",
    })

    logger.LogMouseEvent("btn1", 10, 5, "press", "left")
    logger.LogFocusEvent("btn1", true)
    logger.LogMessage("Button clicked!")
}
```

### 2. 运行被调试程序

```bash
go run main_with_logger.go
```

程序会在控制台显示日志文件位置：
```
[DevTools] Logger started: C:\Users\xxx\.mint\devtools\logs\session_20240130_123456.log
```

### 3. 使用独立调试器分析

```bash
# 自动查找并分析最新日志
mint-debugger

# 指定日志文件
mint-debugger -log C:\Users\xxx\.mint\devtools\logs\session_20240130_123456.log

# 只分析不监控
mint-debugger -analyze-only

# 导出完整报告
mint-debugger -report
```

## API 参考

### Logger

| 方法 | 描述 |
|------|------|
| `NewLogger(config)` | 创建新的日志记录器 |
| `Log(type, target, phase, data)` | 记录通用事件 |
| `LogComponentAdd(id, type, props)` | 记录组件添加 |
| `LogMouseEvent(id, x, y, type, click)` | 记录鼠标事件 |
| `LogFocusEvent(id, focused)` | 记录焦点事件 |
| `LogKeyEvent(id, key, mod)` | 记录键盘事件 |
| `LogMessage(msg)` | 记录普通消息 |
| `LogError(id, msg, err)` | 记录错误 |
| `Close()` | 关闭并保存日志 |

### 日志事件格式

```json
{
  "timestamp": "2024-01-30T14:23:15.123456+08:00",
  "frame": 0,
  "type": "mouse",
  "target_id": "btn1",
  "phase": "target",
  "data": {
    "x": 10,
    "y": 5,
    "type": "press",
    "click": "left"
  }
}
```

## 问题诊断场景

### 场景 1: 程序崩溃后分析

即使程序崩溃，日志文件已经写入，可以事后分析：

```bash
# 程序崩溃后，运行调试器
mint-debugger -analyze-only

# 查看崩溃前的事件流
# 检测异常事件模式
```

### 场景 2: 检测事件丢失

如果预期的事件没有记录：

```
⚠️  没有组件添加事件 - 组件可能未正确注册
⚠️  没有鼠标事件 - 命中测试可能失败
⚠️  检测到鼠标点击但无回调 - onClick 可能未设置
```

### 场景 3: 性能分析

通过事件频率检测性能问题：

```
⚠️  事件频率过高 (1523.45 事件/秒) - 可能存在事件循环
```

| 平台 | 默认位置 |

## 设计思想与架构

### 观察者效应问题

传统嵌入式 DevTools 存在"观察者效应"问题：

```
┌─────────────────────────────────────────────────────────────────┐
│                      问题场景分析                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  场景 1: 程序无法启动                                            │
│  ┌─────────────┐                                                │
│  │  程序启动失败 │ → DevTools 根本无法初始化 ❌                   │
│  └─────────────┘                                                │
│                                                                  │
│  场景 2: 程序崩溃                                                │
│  ┌─────────────┐                                                │
│  │  程序运行中  │                                                │
│  │  [崩溃!💥]   │ → DevTools 随程序一起终止 ❌                    │
│  └─────────────┘                                                │
│       崩溃原因永远无法知道...                                    │
│                                                                  │
│  场景 3: DevTools 本身影响程序                                   │
│  ┌─────────────────────────────────────┐                        │
│  │  程序 + DevTools                   │                        │
│  │  内存占用: 200MB → 250MB (+25%)    │ → 改变程序行为 ❌        │
│  │  CPU 占用: 5% → 15%               │                        │
│  └─────────────────────────────────────┘                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 独立调试器解决方案

```
┌─────────────────────────────────────────────────────────────────┐
│                    Standalone 架构                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐      ┌──────────────┐      ┌──────────────┐  │
│  │   被调试程序  │      │   日志文件   │      │   独立调试器  │  │
│  │              │      │              │      │              │  │
│  │  ┌────────┐  │ 写入 │   .log 文件  │ 读取 │   分析器     │  │
│  │  │ Logger │──┼─────▶│   (JSONL)   │─────▶│   检测器     │  │
│  │  └────────┘  │      │              │      │   报告器     │  │
│  │              │      │              │      │              │  │
│  └──────────────┘      └──────────────┘      └──────────────┘  │
│         │                      │                      │          │
│    崩溃 ✅                 持久化 ✅              独立运行 ✅     │
│    不影响                 可传输                 可事后分析      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 数据流设计

```
时间线:
────────────────────────────────────────────────────────────────▶

t0: 程序启动 → Logger 创建 → session_20240130_123456.log 创建
     ↓
t1: 组件创建 → LogComponentAdd() → 写入日志
     ↓
t2: 用户交互 → LogMouseEvent() → 写入日志
     ↓
t3: [程序崩溃 💥]
     ↓
t4: (程序已终止)
     ↓
t5: 开发者发现崩溃
     ↓
t6: mint-debugger -analyze-only → 读取日志 → 分析原因 ✅
```

### 日志格式设计

使用 JSONL (JSON Lines) 格式，每行一个事件：

```jsonl
{"timestamp":"2024-01-30T14:23:15.123456+08:00","frame":0,"type":"session","target_id":"system","phase":"meta","data":{"event":"session_start","time":"2024-01-30T14:23:15.123456+08:00","file":"..."}}
{"timestamp":"2024-01-30T14:23:15.124456+08:00","frame":1,"type":"component_add","target_id":"btn1","phase":"target","data":{"component_type":"Button","text":"Button 1","x":5,"y":7}}
{"timestamp":"2024-01-30T14:23:17.456789+08:00","frame":123,"type":"mouse","target_id":"btn1","phase":"target","data":{"x":2,"y":1,"type":"press","click":"left"}}
```

**优势:**
- 每行独立可解析 - 单行损坏不影响其他行
- 支持流式写入 - 无需缓冲
- 易于 grep/awk 分析 - 命令行工具友好
- 可追加写入 - 支持多程序写入同一文件

### 问题检测算法

调试器内置多种问题检测模式：

```
1. 事件缺失检测
   ───────────────────────────────────────────────────
   IF component_add == 0 → "组件可能未正确注册"
   IF focus == 0 AND events > 10 → "组件可能未实现 Focusable 接口"
   IF mouse == 0 AND events > 10 → "命中测试可能失败"

2. 事件不匹配检测
   ───────────────────────────────────────────────────
   mouse_clicks > 0 AND callbacks == 0 → "onClick 可能未设置"

3. 性能异常检测
   ───────────────────────────────────────────────────
   events_per_second > 1000 → "可能存在事件循环"

4. 重复事件检测
   ───────────────────────────────────────────────────
   IF event[i] == event[i-1] AND time_diff < 10ms → "检测到重复事件"
```

## 总结

Standalone DevTools 通过**日志文件解耦**的方式，解决了传统嵌入式调试工具的核心问题：

### 核心优势

1. **程序崩溃后仍可分析** - 日志已持久化到磁盘
2. **完全独立运行** - 调试器不依赖被调试程序
3. **支持事后分析** - 可以分析历史日志文件
4. **最小侵入性** - 只写日志，不改变程序行为
5. **问题自动检测** - 内置多种问题检测模式

### 适用场景

| 场景 | 推荐方案 |
|------|----------|
| 生产环境调试 | Standalone (低侵入) |
| 程序崩溃分析 | Standalone (事后分析) |
| 远程用户调试 | Standalone (传输日志文件) |
| 开发时实时调试 | 嵌入式 DevTools (交互性强) |
| 性能分析 | Standalone (不影响性能) |
