## 📋 执行摘要

本报告综合分析了 Mint TUI 框架的事件系统现状，基于以下三个核心文档：

1. `docs/event/long_term_event_architecture.md` - 长期架构规划
2. `framework/docs/ui/idea/idea4.1_event.md` - 事件系统设计理念
3. `framework/docs/EVENT_SYSTEM.md` - V3 事件系统规范

**核心问题**：Inspector overlay 无法响应鼠标事件的根本原因是事件系统存在三个关键断层：
- 命中测试分散（各组件手写 bounds）
- Event → Action 转换缺失
- 异步操作分散（无统一 Cmd 管理）

**推荐方案**：分 6 个阶段重构，优先实现 HitMap 系统，预计 7 周完成。

## 🎯 问题诊断

### Inspector Overlay 鼠标事件失效的根本原因

| 问题 | 当前状态 | 根本原因 |
|------|---------|----------|
| Tab 点击失效 | 需手动计算坐标 | 缺少统一 HitMap，组件 bounds 未正确设置 |
| Hover 检测失败 | `vnodeContains` 返回 false | `ElementVNode` 未实现 `SetBounds` |
| 接口不匹配 | `GetBounds() (int,int,int,int)` ≠ `GetBounds() [4]int` | 类型签名不一致 |
| 事件分发特例化 | Inspector 独立处理事件 | 未纳入统一的阶段化分发流程 |

### 三个关键断层

```
当前事件流（碎片化）
┌─────────────────────────────────────────────────────────────┐
│  Pump → MouseEvent(X,Y)                                     │
│    ├─→ App.dispatchEvent()                                 │
│    │   ├─→ Inspector.HandleMouseEvent() [特例]            │
│    │   │   └─→ 手动坐标解析                                │
│    │   └─→ Component.HandleEvent()                        │
│    │       └─→ 各组件自己 containsPoint() [分散]           │
│    └─→ 缺少: HitMap → TargetID → LocalXY                  │
└─────────────────────────────────────────────────────────────┘
```

**断层 1: 命中测试分散**
- 每个组件需要手动实现 `containsPoint()`
- 缺少统一的 HitMap 自动构建机制

**断层 2: Event → Action 缺失**
- 组件直接处理原始 MouseEvent/KeyEvent
- 缺少语义化的 Action 层

**断层 3: 异步操作分散**
- 组件各自启动 goroutine
- 无统一的 Cmd 管理和生命周期控制

## 🏗️ 统一的事件系统架构

### 完整数据流

```
┌───────────────────────────────────────────────────────────────┐
│  Platform Layer (终端输入)                                     │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  Pump (事件泵)                                                 │
│  • ANSI 解析                                                   │
│  • 生成 RawInput                                               │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  Event System (Runtime Layer)                                  │
│  • RawInput → KeyEvent/MouseEvent                             │
│  • HitMap 构建 (每帧)                                          │
│  • 填充 TargetID/LocalX/LocalY                                │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  InputProcessor + KeyMap (语义化)                              │
│  • KeyEvent → Action (基于上下文)                              │
│  • MouseEvent → Action (基于命中)                              │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  Router (三阶段分发)                                           │
│  1. Capture Phase: Root → Target [Inspector优先级]           │
│  2. Target Phase: Component.HandleAction()                   │
│  3. Bubble Phase: Target → Root                               │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  Component → State Update                                      │
│  • Handler 只能改 State                                        │
│  • 不能直接 Paint                                              │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  Scheduler                                                     │
│  • 标记 dirty                                                  │
│  • 批处理更新                                                  │
└───────────────────────────────────────────────────────────────┘
                          ↓
┌───────────────────────────────────────────────────────────────┐
│  Reconcile → Layout → Paint                                    │
└───────────────────────────────────────────────────────────────┘
```

### 关键设计原则（来自 idea4.1）

1. **事件不能直接触发 Paint**
   - 否则：动画系统失效、Diff 跳过、布局错乱

2. **状态不能在 Render/Measure 修改**
   - 否则：无限循环、布局抖动

3. **输入是"外部流"，状态是"内部流"**
   - Event Flow → 改变 State Flow
   - State Flow → 生成 UI Flow
   - 三者方向固定，不能逆流
